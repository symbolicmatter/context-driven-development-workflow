# BACKLOG

Living coordination surface for candidate, selected, active, blocked, and completed work.

## Purpose

- Coordinate near-term work without overloading PLAN.md
- Provide a clear funnel from idea to SPEC to implementation
- Make active work visible across contributors and agents
- Support parallel work while keeping context traceable

## How to use this file

- Keep items short and actionable
- One line per item
- Move items between sections as status changes
- Link active SPECs for non-trivial work
- Do not put design detail here

## Status conventions

- [idea] early thought, not yet prioritized
- [next] prioritized for near-term execution
- [spec] requires or has a dedicated spec
- [active] currently in implementation
- [blocked] cannot progress due to dependency or decision
- [done] implemented and verified
